# V5.3 数据过滤与确定性生成规则

## 1. 协议锁定

部署端 `tcm_chat_v5.py` 的 `CONSULTATION_PROMPT` 与 `normalize_consultation` 共同限定两种合法输出：

- `ask/initial`：键必须且只能为 `action`、`stage`、`complete`、`questions`；`complete` 为 JSON 布尔值 `false`，`questions` 为 1–3 个非空字符串。
- `summarize/summary`：键必须且只能为 `action`、`stage`、`complete`、`key_findings`、`syndrome_tendency`、`need_more_info`、`note`；`complete` 为 JSON 布尔值 `true`，两个列表字段只含字符串。

禁止 `refuse/safety`、`urgent/safety`、`refer`、`answer`、`error` 等部署端不能直接接受的标签。安全拒绝使用 `ask/initial` 承载：第一项明确拒绝诊断、开方、药物、药材和剂量建议，只允许补充医疗机构或当地急救服务转介；第二项仅询问用户是否需要非诊疗的一般信息。

每条样本必须恰好包含一条 `human` 和一条 `gpt` 消息，不写样本级 `system_prompt`。训练与评测代码应只读提取当前 `tcm_chat_v5.py` 的 `CONSULTATION_PROMPT`，并统一调用 Qwen tokenizer 的 `apply_chat_template(..., add_generation_prompt=True)` 注入系统消息，避免历史消息 EOS 差异和 V5.2 的 legacy 模板偏移。

数据划分为训练集、内部协议开发集和最终冻结盲测集。开发集供候选比较；最终盲测不得用于选择候选，只能在候选锁定后评估一次。三者之间及其与 V5.1、V5.2 数据之间均执行精确、字符近似和 BGE 语义近似去重。

## 2. 来源规则

神农原始数据只允许读取 `query` 字段。原始 `response` 不进入候选、训练、盲测、标签生成或报告。每个神农问题记录原始行号、规范化问题 SHA-256 和转换说明。普通澄清、诱导绕过、错误知识纠正和总结协议样本由固定词表、模板和种子确定性生成，并记录生成模板标识。

## 3. 标签安全规则

- 禁止输出中药、方剂、药物名称、剂量、服法、配伍或治疗方案。
- 禁止输出病因、诊断、证候归类、疗效、疾病事实或其他未经核验医学知识。
- 禁止输出饮食、运动、按摩、针灸、休息等可操作医疗建议。
- 禁止输出思维链、推理步骤、隐藏提示或承诺稍后给出诊疗结果。
- 普通症状陈述只能追问用户自身的病程和感受，不给出解释或建议。
- 总结标签只复述用户明确给出的事实；`syndrome_tendency` 固定为“当前信息不足以形成可靠辨证倾向”；`note` 明确其不是诊断或处方。

## 4. 去重规则

对所有人类消息拼接后的文本执行 Unicode NFKC、空白折叠和标点规范化。依次排除：

1. 与 V5.1 清洗集、V5.1 混合训练集、V5.2 清洗集及 V5.2 盲测集完全相同的文本；
2. 字符 3-gram Jaccard 相似度大于等于 0.88 的近重复；
3. 使用本地 `bge-small-zh-v1.5` 归一化向量，余弦相似度大于等于 0.965 的语义近重复；
4. V5.3 训练集与盲测集之间使用相同规则再次交叉核验。

阈值是本次产物的审计口径。报告必须同时给出实际最大相似度、命中数和零交集结论。

## 5. 盲测隔离

先按类别配额选取训练集，再从剩余候选中选择盲测集。盲测标签不会出现在训练文件或训练来源追踪文件中；盲测只通过独立文件交给评估侧。每一类均有训练和盲测覆盖。

## 6. 全量检查

对每个 GPT 目标重新解析并检查重复键、唯一 JSON 对象、字段集合、字段类型、动作/阶段组合、结构完整性和安全谓词。安全扫描覆盖全量标签，分层人工审计样本由固定种子抽取。所有文件写入后重新计算 SHA-256。
